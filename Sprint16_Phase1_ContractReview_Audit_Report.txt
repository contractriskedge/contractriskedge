5. WORKFLOW STATE AUDIT
================================================================================

5.1 States Defined

  ReviewStatus enum (models.py) — 20 states:
    draft, uploaded, analyzing, ai_analyzed, ai_reviewed, procurement_review,
    legal_review, security_review, negotiation, in_review, changes_requested,
    escalated, legal_approval, exec_approval, approved, rejected, finalized,
    executed, archived, closed

  WorkflowState enum (workflow.py) — 14 states:
    uploaded, analyzing, ai_reviewed, procurement_review, legal_review,
    security_review, negotiation, in_review, escalated, approved, rejected,
    finalized, executed, archived

5.2 CRITICAL GAP: Dual State Definitions

  There are TWO separate state enums that are NOT fully synchronized:

  States in ReviewStatus but MISSING from WorkflowState:
    - draft
    - ai_analyzed
    - changes_requested
    - legal_approval
    - exec_approval
    - closed

  The service.py update_status method uses map_legacy_status() to bridge them,
  but this is a brittle workaround.

  Additionally, the dashboard schema ReviewsByStatus expects:
    draft, ai_analyzed, in_review, pending_approval, approved, rejected,
    escalated, closed

  "pending_approval" is NOT a real state — it is a synthetic aggregation.

5.3 States Actually Used in Database

  Status          | Count | In WorkflowState?
  ----------------|-------|--------------------
  draft           |     1 | MISSING
  ai_analyzed     |   122 | MISSING
  in_review       |    13 | YES
  approved        |    11 | YES
  escalated       |     2 | YES
  legal_approval  |     1 | MISSING

  VERDICT: The workflow state machine is NOT governing actual transitions.
  States like "ai_analyzed" and "legal_approval" are used in the database but
  not defined in WorkflowState. The map_legacy_status() bridge is fragile.

10. EXECUTIVE SUMMARY
================================================================================

  The Contract Review workflow is structurally complete but operationally stalled.

  STRENGTHS:
    - Architecture: 50+ endpoints, 14 ORM models, full state machine, risk delta
      engine, workspace hydration, 3 export formats — enterprise-grade.
    - Frontend: 22 components, 631-line hook layer, adaptive polling, optimistic
      UI — well-engineered.
    - Data Flow: End-to-end chain from upload -> AI -> findings -> redlines ->
      approval -> versioning is intact and verified.

  CRITICAL ISSUES:
    - 81% of reviews are stuck in "ai_analyzed" with no auto-routing mechanism.
    - Dual state enum creates a brittle transition layer (20 states vs 14 states).
    - Zero upload records despite 150 reviews existing in the database.

  MODERATE ISSUES:
    - Only ~55% of AI artifacts (findings/redlines) are imported into reviews.
    - Assignment tracking tables (assignment_audit, assignment_locks) are empty.
    - No seed data for development/testing environments.

  HIGHEST-VALUE ACTIVATION WORK:
    1. Fix the stuck review pipeline (C-01) — auto-route from ai_analyzed
    2. Unify the state machine (C-02) — merge ReviewStatus and WorkflowState
    3. Activate the routing engine (M-03) — seed routing rules

  These three changes will unblock the entire workflow and make the system
  production-viable.
